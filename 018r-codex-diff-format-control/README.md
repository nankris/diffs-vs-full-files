# 018r: edit format × agent workflow

## Preregistered hypothesis and decision rule (before model execution)
H1: for large files, sparse JSON edits reduce output tokens versus whole-file output in BOTH tools-on and tools-off workflows. H2: tools-on adds total-token overhead within each format. These test format and workflow separately; the original 1.7× estimate cannot identify either effect.

Round 1: original 10 tasks plus three 300+ line variants, three formats (full/unified diff/JSON), two workflows, two independent repetitions = 156 calls. All files and tests are pasted identically. Tools-on must use a shell tool to save the requested representation to answer.txt (not edit broken.js); tools-off must return that representation without any tools. A common external grader applies it to an untouched fixture and runs node test.js. This measures an artifact-writing agent loop, not an autonomous debugging agent. Tools-off uses shell_tool=false plus a no-tools instruction and read-only sandbox; any tool call is a protocol violation, not a valid off observation. Other built-in tools may remain advertised; this is not a tool-schema removal experiment.

Primary H1 statistic: average per-task log(full output tokens / JSON output tokens), first averaging repetitions, separately for large files and each workflow. Paired task-cluster percentile bootstrap, 20,000 draws, fixed seed 1801. PROVEN if both 95% CIs exclude zero above; DISPROVEN if either CI excludes zero below; otherwise inconclusive. All contributing cells must have successful application/tests and workflow compliance, else primary inconclusive. H2: task-cluster bootstrap log(on total tokens/off total tokens), separately by format; positive CI supports overhead, negative contradicts it, otherwise unresolved. Unified diff is a prespecified secondary comparison. Small-vs-large crossover shown descriptively, not assumed.

If round 1 primary is inconclusive: redesign ONCE, add three independently structured large tasks (not just repetitions), retain the original tasks, run two new repetitions in every cell. Analyze round 2 separately by the same rule. Stop after two rounds. No optional third round. Bootstrap over three large fixtures has limited generality; padded variants test unchanged context length, not complex code maintenance. No claims of reliability equivalence from these sample sizes.

Token accounting: use turn.completed usage from codex exec --json, retaining input, cached input, output, total, tool events, wall time, raw streams and exact prompts.
